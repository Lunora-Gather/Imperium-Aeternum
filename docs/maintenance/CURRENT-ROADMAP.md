# 当前完善路线图

> 本文是正式版之后唯一的当前优先级入口。历史 `docs/planning/` 文件保留设计过程，不代表尚未完成的待办。

## 当前判断

游戏的规则、存档、共享世界和发布基础已经完整。下一阶段不以继续堆叠系统数量为目标，而是验证决策是否有趣、长局是否耐玩、界面是否稳定，以及线上链路是否持续可用。

## 初版交付基线

- 启动页默认突出推荐开局、续玩与快速指南，完整 10 剧本库按需展开。
- 旧页面遇到新部署导致的失效代码块时，提供明确的刷新恢复入口；本地存档不随刷新清除。
- 桌面与 390px 移动视口覆盖核心页面间距、横向溢出、重复 ID、控件命名、进度语义和模态框键盘焦点。
- 数据自检必须覆盖每一个可选剧本；新增剧本却未配置生成校验时直接阻止发布。
- 机器门禁负责正确性、稳定性、布局和部署完整性；真人测试只承担乐趣、理解成本和策略平衡判断。

## P0 · 真人体验与平衡

- 按 [`../playtesting/20-TURN-PROTOCOL.md`](../playtesting/20-TURN-PROTOCOL.md) 完成经典、区域、世界和挑战四类实测。
- 每局必须记录 20 个真实决策，不得用自动推进或稳定性模拟代替。
- 固定最优策略连续出现四回合、连续三回合没有主要决策或挑战局缺少恢复路线，必须形成平衡问题。
- `npm run simulate:long` 只负责发现数值崩溃、压力分布和性能问题，不能给出“好玩”的结论。

## P1 · 长局操作与信息密度

- 省份列表提供搜索和风险、人口、名称排序。
- 世界地图提供国家/省份搜索、边境和本国高风险筛选。
- 统计页持续展示近期财政、粮食、战争和反馈密度体检。
- 新增批量操作前必须证明它减少重复点击，同时不会替玩家做战略选择。

## P1 · UI 与无障碍

- 核心页面统一使用页面栈间距，不依赖相邻卡片各自补外边距。
- 浏览器门禁覆盖桌面和 390px 视口、横向溢出、图表宽度、控件命名和重复 ID。
- 新增固定列网格必须有窄屏布局；新增 SVG 交互节点必须支持键盘和可访问名称。
- 内联样式按触达文件逐步收敛，不做高风险的一次性重写。

## P1 · 线上可靠性

- Pages 构建和浏览器冒烟通过后才能部署。
- 部署完成后必须从公开 URL 重新读取 HTML、CSS 和入口 JavaScript，确认根节点、资源、版本标记和关键布局契约存在。
- Appwrite Functions 的状态检查与真实认证写入测试分开；生产数据写入只能使用专用测试账号和隔离资源。

## P2 · 重玩价值

- 优先让国家、剧本、AI 长期目标和危机链产生不同局势，不以继续增加独立事件数量作为主要指标。
- 难度继续以剧本压力与可见恢复路线为主；新增同剧本难度修正前，先用真人记录证明需求。
- 战争维持战略层结算，不引入即时战斗或战术单位操控。

## 每次发布的证据

```bash
npm run test:e2e
npm run simulate:long
VITE_BASE=/Imperium-Aeternum/ npm run rc:check
npm run verify:production
```

人工体验记录与上述机器检查缺一不可；二者回答的是不同问题。
